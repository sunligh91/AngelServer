## 项目简介

**某游戏**是一款基于 **Unity IL2CPP** 的游戏。本项目通过逆向分析其网络协议、
主数据与客户端资源加载路径，实现了一套**本地离线服务端**：

- 客户端通过 BepInEx 插件把 API 与 CDN 请求重定向到本机
- 服务端复现官方的请求/响应契约，并用**玩家自己客户端里的资源文件**作答
- 全程不联网，仅监听 `127.0.0.1`

**本仓库只包含我们编写的代码。** 游戏客户端、主数据、美术与音频等一切原始资产均由
使用者**自备**，详见 [前提条件](#前提条件)。

## 特性

- ✅ **本地离线服务端** — `server.py`：纯标准库的 HTTP 服务，无第三方依赖
- ✅ **完整 API 契约** — 复现登录、用户、任务、战斗、休闲区、交换所、抽卡等 200+ 端点
- ✅ **资源本地化** — 解析客户端自己的 AssetBundle 索引，按需回发
- ✅ **客户端重定向** — 配套的 BepInEx 插件把 API/CDN 源地址改写到本机（插件随发布包提供，**源码不在本仓库**）
- ✅ **两种产品通吃** — 同一服务端同时服务全年龄版与 R 版（各自的 catalog 与资源池）
- ✅ **自带运行环境** — 发布包内含嵌入式 Python，使用者无需安装任何东西

## 前提条件

**你必须已经拥有该游戏的客户端。** 本仓库不提供、也不包含：

| 内容 | 说明 |
|---|---|
| 游戏本体 | 游戏主程序与 `*_Data/` 目录 |
| 游戏资源 | AssetBundle、图片、音频、文本 |
| 主数据 | `masterdata.bundle`、各类 master 表 |
| 资源清单 | `catalog.bin`、索引文件 |
| 存档数据 | 任何玩家记录 |

把这些放在下面的目录结构里，服务端会自动使用：

```
<工作目录>/
├── client/            # 你的游戏客户端（原始目录保持不变）
├── server/            # 本仓库的代码 + 你自备的数据
│   ├── server.py      # ← 本仓库
│   ├── db_new/        #   存档目录（首次运行自动生成）
│   └── ...            #   ← 以下由工具从你的客户端生成
└── runtime/           # 运行环境（可选，见下）
```

## 快速开始

### 方式一：使用已打包的发布版（推荐）

发布包已经包含运行环境与全部资源，解压后双击即可：

```
run_allages.cmd
```

### 方式二：从本仓库自行搭建

需要 **Python 3.11+**（或用嵌入式发行版）：

```cmd
cd <工作目录>\server
set ANGELICA_PORT=18080
set ANGELICA_USER=new
python server.py
```

然后启动客户端（`client\` 目录下的游戏主程序）。

服务端只监听 `127.0.0.1`，启动后日志会输出身份与存档信息。

## 工作方式

```
┌──────────────┐   HTTP (被重定向)   ┌──────────────┐
│   游戏客户端  │ ──────────────────> │  本地服务端   │
│  游戏主程序  │                     │  server.py   │
└──────┬───────┘                     └──────┬───────┘
       │ BepInEx 插件改写                  │ 读取
       │ （插件随发布包提供）              │ 客户端自带的资源
       ▼                                  ▼
  127.0.0.1:18080                  client/**/Caches/**
```

| 端点 | 作用 |
|---|---|
| `/api/**` | 游戏业务接口，复现官方契约 |
| `/res/v1/**` | 资源与清单（catalog、bundle、文本、图片）|
| `/api/sdk/request` | 接收并静默处理 DMM SDK 请求 |

### 关键设计

- **资源不下发**：服务端只把客户端**自己已有的**文件按索引再发一次
- **契约优先**：每个端点的响应形状都对照真实抓包验证，而非凭字段名推测
- **数据驱动**：主数据、资源索引均从使用者本地客户端生成，仓库内不含任何资产

## 构建与使用

**服务端无需构建** — 它只用标准库，直接用 Python 运行即可（见[快速开始](#快速开始)）。

### 服务端环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `ANGELICA_PORT` | `18080` | 监听端口 |
| `ANGELICA_USER` | （空）| 选择存档目录：空 → `db/`，`new` → `db_new/` |
| `ANGELICA_EXTRA_BUNDLES` | （空）| 额外资源池路径，多个用 `;` 分隔 |
